第一章  为什么两个USB接口速度相同，带宽却不同
================================================================================

CH32V208 芯片上的两个 USB 接口均为 USB Full-Speed（12 Mbps），但它们来自
完全不同的硬件 IP 核，底层缓冲架构截然不同，导致可用的端点包大小存在本质
差异，进而影响每条方向的实际有效带宽。

────────────────────────────────────────────────────────────────────
1.1  两个 USB IP 核的硬件对比
────────────────────────────────────────────────────────────────────

  特性                USBFS（WCH 原生 IP）         USBD（STM32 兼容 IP）
  ──────────────────  ─────────────────────────   ──────────────────────────
  寄存器基地址        0x5000_0000                  0x4000_5C00
  端点缓冲架构        DMA 直接访问系统 SRAM         专用 PMA 双口 RAM
  PMA 地址            无（直接用系统 SRAM）          0x4000_6000（固定 512 B）
  最大可用缓冲        受限于系统 SRAM（32 KB）       固定仅 512 字节
  数据传输方式        硬件 DMA，零 CPU 拷贝          CPU 手动拷贝
                                                    UserToPMABufferCopy()
  ISO 大包支持        ✅ 支持（本项目用 192 B/ms）   ❌ 最多 64 B/ms
  驱动代码            APP/ch32v20x_usbfs_device.c  APP/USBLIB/ 全库
  时钟来源            RCC_AHBPeriph_USBFS           RCC_APB1Periph_USB
  连接对象（本项目）   HOST                          TARGET

  代码证据：
    // APP/include/ch32v20x_usbfs_device.h
    #define USBFSD_UEP_MOD_BASE  0x5000000C   // USBFS 端点模式寄存器基址
    #define USBFSD_UEP_DMA_BASE  0x50000010   // USBFS DMA 地址寄存器基址

    // APP/USBLIB/USB-Driver/inc/usb_regs.h
    #define RegBase  (0x40005C00L)             // USBD 寄存器基址
    #define PMAAddr  (0x40006000L)             // PMA 专用内存地址

────────────────────────────────────────────────────────────────────
1.2  USBFS 的 DMA 架构（无 PMA 限制）
────────────────────────────────────────────────────────────────────

  USBFS 端点缓冲区直接在系统 SRAM 中声明，初始化时将 SRAM 地址写入 DMA
  寄存器，硬件自动完成 USB 数据与 SRAM 之间的搬运，CPU 无需参与。

  // APP/ch32v20x_usbfs_device.c — 缓冲区声明
  __attribute__((aligned(4))) uint8_t USBFS_EP0_Buf[64];
  __attribute__((aligned(4))) uint8_t USBFS_EP1_Buf[64];   // 键盘 IN
  __attribute__((aligned(4))) uint8_t USBFS_EP2_Buf[64];   // 鼠标 IN
  __attribute__((aligned(4))) uint8_t USBFS_EP3_Buf[64];   // 绝对鼠标 IN
  __attribute__((aligned(4))) uint8_t USBFS_EP4_Buf[64];   // 媒体键 IN
  __attribute__((aligned(4))) uint8_t USBFS_EP5_Buf[192];  // UAC ISO IN  ← 192 B
  __attribute__((aligned(4))) uint8_t USBFS_EP6_Buf[192];  // UAC ISO OUT ← 192 B

  // 初始化时直接把 SRAM 地址写入 DMA 寄存器
  USBFSD->UEP5_DMA = (uint32_t)USBFS_EP5_Buf;
  USBFSD->UEP6_DMA = (uint32_t)USBFS_EP6_Buf;

  // 端点模式寄存器：同时使能 EP5 TX 和 EP6 RX
  USBFSD->UEP5_6_MOD = USBFS_UEP5_TX_EN | USBFS_UEP6_RX_EN;

────────────────────────────────────────────────────────────────────
1.3  USBD 的 PMA 架构（512 字节硬性限制）
────────────────────────────────────────────────────────────────────

  USBD 使用 STM32 兼容的 PMA（Packet Memory Area）双口 RAM，总容量仅 512 字节。
  所有端点的发送/接收缓冲区必须从这 512 字节中划分，由 BTABLE 管理地址。
  每次数据传输均需 CPU 调用专用函数在 PMA 与系统 SRAM 之间拷贝数据。

  PMA 寻址宏（APP/USBLIB/USB-Driver/inc/usb_regs.h）：
    #define _pEPTxAddr(bEpNum)  ((uint32_t *)((_GetBTABLE()+bEpNum*8  )*2+PMAAddr))
    #define _pEPRxAddr(bEpNum)  ((uint32_t *)((_GetBTABLE()+bEpNum*8+4)*2+PMAAddr))

  CPU 手动拷贝（APP/uac_handler.c 中使用）：
    // 发送前：SRAM → PMA
    UserToPMABufferCopy((uint8_t *)src, ENDP4_ISO_TXADDR, UAC_USBD_ISO_PACKET_SIZE);
    SetEPTxCount(ENDP4, UAC_USBD_ISO_PACKET_SIZE);
    SetEPTxStatus(ENDP4, EP_TX_VALID);

    // 接收后：PMA → SRAM
    PMAToUserBufferCopy(usbd_tmp, ENDP5_ISO_RXADDR, copy_len);

────────────────────────────────────────────────────────────────────
1.4  结论：速度相同，架构不同
────────────────────────────────────────────────────────────────────

  两个接口都跑在 12 Mbps Full-Speed 总线上，理论带宽完全相同。
  差异来自缓冲区容量：

  - USBD 的 PMA 只有 512 字节，分配给 6 个端点后每个 ISO 端点只剩 64 字节，
    所以 USBD 侧音频只能用 16 kHz（64 B/ms）。

  - USBFS 直接用系统 SRAM，DMA 搬运，EP5/EP6 各分配 192 字节缓冲，
    轻松支持 48 kHz（192 B/ms）。

  类比：两辆车速度相同，USBD 的车厢只有一个 64 字节小箱子（PMA），
        USBFS 的车厢可以直接装 192 字节大箱子（SRAM + DMA）。

2.3  USBD 音频 ISO 端点为何最大只能 64 字节？
────────────────────────────────────────────────────────────────────

  根本原因：USBD PMA 总共 512 字节，各端点分配如下：

    区域                   大小     说明
    ─────────────────────  ──────   ──────────────────────────────────
    BTABLE（描述符表）      64 B     端点地址表，不可省略
    EP0（控制端点）         64 B     枚举必须，不可省略
    EP1 INT IN（CDC 控制）   8 B     CDC 控制中断
    EP2 BULK OUT（CDC 数据） 32 B    已从 64 B 缩减
    EP3 BULK IN（CDC 数据）  32 B    已从 64 B 缩减
    ─────────────────────  ──────
    已用小计               200 B
    剩余可用               312 B

    EP4 ISO IN（音频）       64 B    目标 mic → 主机 spk
    EP5 ISO OUT（音频）      64 B    主机 mic → 目标 spk
    未使用剩余              184 B   （不足以再放另一个 192 B ISO 端点）

  描述符中的注释（APP/USBLIB/CONFIG/usb_desc.c 第 108 行）：
    /* Constrained by USBD PMA: 512 B total, 448 B already used by EP0-3 */

  结果：为使 64 B/ms 对应整数采样率，选择 16 kHz（64 = 16000/1000 × 2 × 2）。
  这正是音频桥接层需要 3× 重采样的原因（16 kHz ↔ 48 kHz）。

3.3  音频信号流向（来自 uac_handler.c 文件头注释）
────────────────────────────────────────────────────────────────────

  ┌─────────────────────────────────────────────────────────────────────────┐
  │  Host PC mic  ──USBD EP5 OUT──► h2t_buf ──USBFS EP5 IN──► Target spk   │
  │  Target mic   ─USBFS EP6 OUT──► t2h_buf ──USBD EP4 IN──►  Host PC spk  │
  └─────────────────────────────────────────────────────────────────────────┘

  ══════════════════════════════════════════════════════════════════════════
  方向 1：主机 PC 麦克风 → 目标 PC 扬声器（Host→Target，h2t）
  ══════════════════════════════════════════════════════════════════════════

    主机 PC 麦克风
       │  USB ISO OUT  16 kHz 立体声 16-bit，64 B/ms
       ▼
    USBD EP5 OUT (0x05)                   [STM32 兼容 USB 外设，PMA]
       │
       │  EP5_OUT_Callback()              [APP/USBLIB/CONFIG/usb_endp.c]
       │    GetEPRxCount(ENDP5) 获取长度
       │    → UAC_USBD_EP4_RxDone(len)
       ▼
    UAC_USBD_EP4_RxDone(len)              [APP/uac_handler.c]
       │  PMAToUserBufferCopy(usbd_tmp, ENDP5_ISO_RXADDR, len)  PMA→SRAM
       │  write_slot = g_h2t_wr ^ 1
       │  up_sample_3x(usbd_tmp[64B] → g_h2t_buf[slot×192B])   16kHz→48kHz
       │  g_h2t_wr = write_slot;  g_h2t_rdy = 1
       │
       │  ⚠ 注意：此处不可调用 SetEPRxStatus(ENDP5, EP_RX_VALID)
       │    ISO OUT 端点的 STAT_RX 是 SW_BUF 切换位，非 NAK/VALID 控制位。
       │    硬件每帧自动重新接收，手动切换会导致 PMA 地址错误 → 噪声/静音交替。
       ▼
    g_h2t_buf[192 × 2]（乒乓缓冲区，槽 0/1 交替写入）
       ▼
    UAC_USBFS_EP5_TxDone()                [APP/uac_handler.c]
       │  （由 USBFS IRQ 每 1 ms 调用一次）
       │  if g_h2t_rdy:
       │    memcpy(USBFS_EP5_Buf ← g_h2t_buf[g_h2t_wr×192], 192B)
       │    g_h2t_rdy = 0
       │  else:
       │    memcpy(USBFS_EP5_Buf ← g_silence_192, 192B)  // 无新帧→发静音
       │  UEP5_TX_LEN  = 192
       │  UEP5_TX_CTRL = T_RES_NONE（ISO IN，无需 ACK）
       ▼
    USBFS EP5 IN (0x85)                   [WCH USBFS，DMA 自动传输]
       │  48 kHz 立体声 16-bit，192 B/ms
       ▼
    目标 PC 扬声器

  ══════════════════════════════════════════════════════════════════════════
  方向 2：目标 PC 麦克风 → 主机 PC 扬声器（Target→Host，t2h）
  ══════════════════════════════════════════════════════════════════════════

    目标 PC 麦克风
       │  USB ISO OUT  48 kHz 立体声 16-bit，192 B/ms
       ▼
    USBFS EP6 OUT (0x06)                  [WCH USBFS，DMA 自动写入 USBFS_EP6_Buf]
       │
       │  USBFS IRQ 处理                  [APP/ch32v20x_usbfs_device.c]
       │    → UAC_USBFS_EP6_RxDone(len)
       ▼
    UAC_USBFS_EP6_RxDone(len)             [APP/uac_handler.c]
       │  src = USBFS_EP6_Buf（单缓冲，DMA 始终写 offset 0）
       │  write_slot = g_t2h_wr ^ 1
       │  if len == UAC_ISO_PACKET_SIZE(192):
       │    down_sample_3x(src[192B] → g_t2h_buf[slot×64B])  48kHz→16kHz
       │  else:
       │    先 memset+memcpy 补齐到 192B，再 down_sample_3x（处理短帧）
       │  g_t2h_wr = write_slot;  g_t2h_rdy = 1
       ▼
    g_t2h_buf[64 × 2]（乒乓缓冲区，槽 0/1 交替写入）
       ▼
    UAC_USBD_EP3_TxDone()                 [APP/uac_handler.c]
       │  （由 USBD EP4_IN_Callback 每 1 ms 调用一次）
       │  if g_t2h_rdy:
       │    src = g_t2h_buf + g_t2h_wr * 64
       │    g_t2h_rdy = 0
       │  else:
       │    src = g_silence_64              // 无新帧→发静音
       │  UserToPMABufferCopy(src, ENDP4_ISO_TXADDR, 64)  SRAM→PMA
       │  SetEPTxCount(ENDP4, 64)
       │  if g_uac_state.usbd_as_in_alt:   // 仅在 alt1 激活时才重新 arm
       │    SetEPTxStatus(ENDP4, EP_TX_VALID)
       │  else:
       │    SetEPTxStatus(ENDP4, EP_TX_DIS)
       ▼
    USBD EP4 IN (0x84)                    [STM32 兼容 USB 外设，从 PMA 发送]
       │  16 kHz 立体声 16-bit，64 B/ms
       ▼
    主机 PC 扬声器

────────────────────────────────────────────────────────────────────
3.4  采样率转换算法详解
────────────────────────────────────────────────────────────────────

  代码文件：APP/uac_handler.c

  ① 上采样 16 kHz → 48 kHz（up_sample_3x）
  ────────────────────────────────────────
  输入：usbd_tmp[64]  = 16 个立体声样本（每样本 4 字节：L_lo, L_hi, R_lo, R_hi）
  输出：g_h2t_buf[192] = 48 个立体声样本

  方法：将每个样本原样重复 3 次（零阶保持，不做线性插值）

  代码实现（逐字节展开，无 memcpy 开销）：
    for i in 0..16:
        s = src + i*4
        d = dst + i*12
        d[ 0..3]  = s[0..3]   // 第 1 次重复
        d[ 4..7]  = s[0..3]   // 第 2 次重复
        d[ 8..11] = s[0..3]   // 第 3 次重复

  ② 下采样 48 kHz → 16 kHz（down_sample_3x）
  ────────────────────────────────────────
  输入：USBFS_EP6_Buf[192] = 48 个立体声样本
  输出：g_t2h_buf[64]  = 16 个立体声样本

  方法：每 3 个样本取第 0 个（直接抽取，无低通滤波）

  代码实现：
    for i in 0..16:
        s = src + i*12   // 取第 0, 3, 6, ... 个样本
        d = dst + i*4
        d[0..3] = s[0..3]

  ⚠ 注意：两个函数均为最简整数倍重采样，未使用低通 FIR/IIR 滤波器。
    上采样会产生阶梯状波形（零阶保持失真）。
    下采样会产生混叠（奈奎斯特频率以上信号折叠到基带）。
    对于 KVM 远控语音通信场景，此精度已足够使用。

────────────────────────────────────────────────────────────────────
3.5  乒乓缓冲机制
────────────────────────────────────────────────────────────────────

  代码文件：APP/uac_handler.c（静态变量，BSS 段）

  h2t 方向（Host→Target，16kHz→48kHz）：
    static uint8_t          g_h2t_buf[192 * 2];  // 2 槽，每槽 192 字节
    static volatile uint8_t g_h2t_wr  = 0;       // 写指针（当前已写槽索引）
    static volatile uint8_t g_h2t_rdy = 0;       // 1 = 有新帧未读取

  t2h 方向（Target→Host，48kHz→16kHz）：
    static uint8_t          g_t2h_buf[64 * 2];   // 2 槽，每槽 64 字节
    static volatile uint8_t g_t2h_wr  = 0;
    static volatile uint8_t g_t2h_rdy = 0;

  静音帧（BSS 段自动清零，无需显式初始化）：
    static const uint8_t g_silence_192[192];     // USBFS 侧静音帧
    static const uint8_t g_silence_64 [ 64];     // USBD 侧静音帧

  乒乓逻辑：
    写入：write_slot = g_Xwr ^ 1              // 总是写"另一槽"
          （处理完毕后）g_Xwr = write_slot；g_Xrdy = 1
    读取：读取 g_Xbuf + g_Xwr × PacketSize   // 总是读"最新槽"
          若 g_Xrdy == 0，改发静音帧

  此设计保证：即使 USB 两侧时钟存在微小漂移，读写不会互相阻塞；
              最坏情况下发一帧静音，不会引起爆音或撕裂。
